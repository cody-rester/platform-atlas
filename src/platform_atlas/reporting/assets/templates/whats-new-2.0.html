What's New in 2.0

The biggest Atlas release yet — a third audit tier for standalone gateways, three explicit credential backends, file-based Gateway 5 capture, and a WebUI that keeps step. Here's everything new across the CLI and the WebUI.

Headline

The big ones

The features that reshape how you set up environments and run audits.

CLI + WebUI

A new SaaS tier

Audit a single standalone Automation Gateway — Gateway 4 or Gateway 5 — with no Platform, MongoDB, or Redis anywhere in the flow: no prompts, no credentials, no collectors. Pick it at environment create; the wizard asks only what that gateway needs and produces one merged report with the Architecture Overview built in.

CLI + WebUI

Three credential backends

Choose where each environment's secrets live — OS Keyring, an Encrypted Local File (AES-256-GCM), or HashiCorp Vault — at setup. Atlas uses exactly that store on every run: no probing, no automatic fallback, no surprise switches. The encrypted file is now a first-class choice for headless hosts.

CLI + WebUI

Gateway 5 from a file

A containerized Gateway 5 no longer needs SSH. Point Atlas at a Docker Compose or Helm values file and it reads the GATEWAY_* configuration straight from disk — the same gateway5 rules evaluate identically whichever source provided the values. Or point it at a server install's own gateway.conf over SSH — only a server-mode config is accepted.

WebUI

Platform asset export

Add Workflows, JST transformations, JSON Forms, or whole Projects to a support bundle. Atlas exports them over Platform OAuth into an exports/ folder in the ZIP — no more exporting each item from the Platform UI by hand. A fast picker modal with search and pagination makes selection painless.

CLI

A real delivery package

session export now bundles the full report set, a freshly generated machine-readable report.json, the session metadata, and a README — named ATLAS-<org>-<session>-<date> so a delivered archive stays traceable to a customer. Attach it straight to an Itential Enablement Request ticket.

CLI + WebUI

Architecture, on your schedule

The architecture interview no longer interrupts capture. Record or update an environment's architecture any time with the new env architecture command (browser form or CLI prompts), and a finished form is recognized and reused silently — never re-asked.

Also new

More in this release

Legacy 2023.x hiddenCLI + WebUI

2023.x rulesets and profiles stay bundled but disappear from every listing and picker — including the Cmd+K palette and Continuous page — unless an environment is actually marked legacy.

2 new Gateway 5 rulesCLI

IAG-035 and IAG-036 audit the IAG5 virtual-environment pruner's sweep interval and retention period against their defaults — 121 rules total.

SSH that grew upWebUI

The environment form gained a ~/.ssh key picker, an inline passphrase stored in the env's own credential store, and a Test SSH connection button that uses the real capture transport.

Setup, reimaginedWebUI

The first-run wizard's Mode step is an equal-thirds accordion across Standard / Extended / SaaS, and a SaaS first-run sets SaaS as your global default for new environments.

config doctor, clearerCLI + WebUI

Grouped into a tree by area in the CLI; in the WebUI a deliberately-chosen encrypted file reads as OK (not a warning), and credential fixes link straight into the app.

Profiles are always realCLI + WebUI

An audit always runs with a profile, so the interactive pickers and dropdowns no longer offer a confusing "None" — they preselect the active or first available profile.

Reliability

Fixes & hardening

Headless keyring no longer crashes — or silently stores secrets in plaintext. The broken automatic alt-keyring switch is gone; on a headless host you now choose the encrypted file backend explicitly.
HA replica-set MongoDB URIs no longer crash credential encoding. A seed-list-safe encoder handles multi-host connection strings instead of failing to parse the port.
Capture no longer re-asks architecture you already entered. Completeness is derived from actual section coverage, and a stale in_progress flag is healed.
report --format json — and the bundled report.json — now pass their own schema validation, documenting the tier field and treating architecture fields as optional.
WebUI: Standard environments no longer show Extended-only questions. The create/edit form is tier-reactive — choosing Standard hides the SSH, topology, and Kubernetes step entirely.
WebUI: Settings saves take effect immediately (Debug logging included), and a SaaS global default is no longer silently reset to Standard on save.
Encrypted-file store is sturdier. Concurrent writes take a lock and merge instead of clobbering, and a damaged key salt is never silently overwritten over still-recoverable credentials.
